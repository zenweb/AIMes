## 复盘 — 今天的方法论得失

### 做对的事

1. **CEO 反思真的产生了战略转向**，不是橡皮图章。从 6 类 Agent 平台铺陈砍到 1 类 Agent 单点引爆，砍幅 83%。
2. **决策追溯完整**，4 个决策的备选项、推荐、理由都留痕。
3. **POC 漏斗给"立即可做"清单**，不是空头规划。
4. **CEO 视角拷问关键前提**："买家是谁？"——平台路径通篇没回答，单点路径锁定为"制造业老板（卖 OTD 改善）"。
5. **避免吹牛的设计内置**：单点路线图把"如何发现 OTD 改善是噪音"写进 A/B 框架，不让数字虚高变成销售陷阱。

### 做错的事（接住这些教训）

1. **假版本号**：v2.0 → v2.1 → v3.0 在一个下午里跳了三次。其实 v2.0 和 v2.1 只是同一份文档的两次扩写，根本不是独立版本。教训：**版本号是相对稳定的快照标记，不是迭代过程中的标签**。本次整理已废除版本号，改用语义化的"路线图"和"愿景"区分。
2. **命名说不清谁是当前**：原 `AI_MES_GAP_AND_ROADMAP.md`（无版本号）vs `AI_MES_V3_FOCUS.md`（有版本号）从名字看不出谁是执行口径。本次重命名为 `ai-mes-roadmap.md`（当前执行）+ `ai-mes-future-vision.md`（推迟愿景），名字直接表达角色。
3. **无入口/索引**：1313 行散在 6 个文件无导航。本次在 roadmap 头部加了文档索引表。
4. **文章内容只活在对话里**：那篇微信文章是这一切的起点，但之前没沉淀到任何文档。本次在 roadmap 加了"缘起"章节摘录文章核心观点和关键证据。
5. **决策记录只在 changelog**：D1-D4 是核心战略决策，本应在主文档高亮。本次把决策记录前置到 roadmap 头部，作为后续所有章节的"为什么"。
6. **3 份分项 changelog 给读者甩头**：早晨写的"我们要做 CLI/Skill/Agent 三层架构"，下午写的"砍掉那些只做单点"。本文（session digest）就是为了消除这种甩头。
