# 2026-05-21 风险 SLA 逾期晨会复核包

## 背景

风险处置队列已经支持转派、升级和关闭，但还缺少管理层每天晨会需要的 SLA 聚合视角：哪些风险逾期、哪些关键风险会影响 OTD、谁负责下一步、复核结论如何进入排产和审计。本次把单卡片处置推进为可复盘的风险 SLA 晨会包。

## 变更

- 新增 `risk-sla-review-sync.ts`，保存 `aimes_risk_sla_review`，并写入统一 `OTD 复盘证据链` 的 `风险 SLA 复核` 阶段。
- `风险预警` 的风险处置队列新增 `生成 SLA 晨会复核包`：
  - 生成 `风险 SLA 逾期晨会复核包`。
  - 固化 `RISK-DAILY-20260521-001`、逾期数量、关键风险数量、影响对象、OTD 影响、责任动作、审计编号和追踪编号。
  - 展示前三个复核风险和 AI 排产、采购协同、设备维护、系统治理四类责任动作。
- `AI 排产` 事件队列新增 `风险 SLA 复核` 事件，读取同一条复核包并生成“晨会复核后的排产保护建议”。
- `AI 生产助手` 可回答“风险 SLA 晨会复核情况？”，输出晨会编号、风险概览、关键风险、责任动作和审计追踪。
- `系统管理` Agent 治理新增风险 SLA 晨会治理卡，展示逾期/关键风险、影响对象、责任动作数量和审计编号。
- `报表中心` CSV 导出新增 `风险SLA复核 / 风险SLA风险项 / 风险SLA责任动作` 行。
- `审计日志` 复用统一 OTD 证据链，自动回放 `TRACE-RISK-SLA-DAILY-REVIEW-20260521`。
- 继续把晨会复核包推进到责任动作闭环：
  - `风险预警` 新增 `确认责任动作闭环`，闭环后生成 `AUD-RISK-SLA-CLOSURE-20260521 / TRACE-RISK-SLA-DAILY-REVIEW-CLOSED-20260521`。
  - 闭环状态会把 OTD 证据链中的 `风险 SLA 复核` 从 active 覆盖为 closed。
  - `AI 排产` 读取闭环状态后，事件卡降级为 `已缓解`，按钮切换为 `复核排产影响`，Agent 建议改为闭环后的承诺窗口复核。
  - `AI 生产助手`、`系统管理` Agent 治理和报表 CSV 会展示闭环追踪号、闭环结论和责任动作结果。

## 验证

- `npx vue-tsc --noEmit -p tsconfig.json`：通过。
- `npm run test:e2e -- tests/e2e/risk.spec.ts`：4 passed，已覆盖晨会复核包生成、责任动作闭环、排产复核、助手问答、治理、报表和审计回放。

## 风险

- 复核包仍是前端本地演示态记录，后续需要接入后端任务、真实 SLA 时钟、责任人确认和次日未关闭追踪。
