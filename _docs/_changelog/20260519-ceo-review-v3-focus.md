# 2026-05-19 CEO 战略反思 — 路线图 v3.0 单点引爆

## 触发
基于 v2.1 路线图执行 plan-ceo-review，对路线图根本前提做拷问。结果：v2.1 的"AI MES 指挥系统"愿景在战略上正确，但对一人/小团队来说资源约束不匹配。锁定 C 路线（单点引爆）作为执行口径。

## 战略决策（4 个）

### D1 — 主战场选择
**结论**：C 单点引爆（数据标杆）

放弃 v2.1 的 6 类 Agent + MCP 协议 + 6 类工作台铺陈，火力全部打透"调度员 Agent + 排产优化 Skill"，用一个可量化业务证据（如固纬电子 50% 缺陷率改善的同等数据点）撬开市场。

### D2 — v2.1 处理
**结论**：B 双文档并存

v2.1 作为 v4 平台化愿景存档保留（多 Agent 设计、MCP 架构思考、6 类工作台不丢），v3.0 作为当前唯一执行口径。在 v2.1 顶部加废弃旗标 + 重定向到 v3.0。

### D3 — 主指标锁定
**结论**：交期达成率 ↑（On-Time Delivery Rate, OTD）

跨业务场景通用，是所有制造业老板听得懂的语言。V1 现有 EDD/WSPT 策略直接对该指标优化，Agent 推荐天然服务于此目标。销售故事："我们的调度员 Agent 把交期达成率提升了 X%"。

### D4 — 标杆数据来源
**结论**：Demo A/B + POC 工厂双轨同时启动

- 轨道 1：演示数据集 A/B（4-8 周出货，作为销售材料）
- 轨道 2：POC 工厂寻找（3-6 个月，现场数据点）
- 互为补强：demo 数据是 POC 客户招募材料，POC 数据反哺销售材料

## v3.0 相对 v2.1 的新增

v2.1 完全缺失但 C 路线必须有：

- **基线对比框架**：基线（人工排产 / FCFS / 纯 EDD）vs Agent 推荐
- **A/B 量化护栏**：≥30 工单 + ≥3 场景 + 蒙特卡洛 + 95% 置信区间
- **反向有效性问题**："如果 OTD 改善是噪音，我们怎么发现？"
- **可信度坦白**：明确标注 demo 数据 vs 现场数据的可信度边界
- **POC 客户漏斗**：行业人脉 / 社群 / 提案模板 / 数据使用权换部署

## 核心洞察

1. **v2.1 不是错的，是"目前不该做的"**。等 v3.0 跑出 POC 现场数据后回到 v2.1 续接扩张。
2. **CEO 视角的关键拷问**：买家是谁？v2.1 通篇没回答。v3.0 答案：制造业老板（卖 OTD 改善），不是 IT（卖 AI MES 平台）。
3. **路径依赖警告**：v0.1.0 已冻结商业版边界。v3.0 必须在这个边界内执行。
4. **平台路径不是放弃，是后置**。"willfulness as strategy"——单点先做透，再扩展，比同时下两个注更可能成功。
5. **避免吹牛的设计内置**：v3.0 把"如何发现 OTD 改善是噪音"写进框架，不让数字虚高变成销售陷阱。
