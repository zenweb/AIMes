### 关键设计决策

**为什么截图而非 mp4**：本机无录屏环境，但**如果只交付脚本和字幕，下次录屏人会再次踩到"屏幕长什么样"的盲点**。5 张真实截图代替临时占位图，让外部录屏人在没本地环境时也能按 storyboard 重现镜头。

**为什么 spec 化截图而非手动**：spec 化让"重生成截图"等同于"跑一次 e2e"，每次 `latest-ab-report.json` 变化都能自动验证脚本/字幕/截图三者还对得上。

**为什么把 5 角色矩阵写进字幕**：B 类 T-31 是 5/23 当天最大的产品价值点之一，但之前的 srt（Codex 写于 5/24）还在讲 Admin-only adoption。第 3 cue 升级为"five-role permission matrix"反映真实能力。

## 关键洞察

1. **T-33 暴露了一个"AI 不能做但能极大降低做的成本"的真实场景**：录屏 + 配音是物理动作，AI 做不到；但脚本/字幕/截图与真数字的 100% 对齐是 AI 的强项。把"做不到"和"能做的"分清楚比假装做完整件事更诚实。

2. **数据 → 脚本 → 字幕 → 截图四者绑定的工程化**：通过 spec 把截图机器化、通过 versioning rule 把脚本与 `latest-ab-report.json` 绑定，未来无论谁来录 mp4 都不会跑出旧数字。这才是 T-33 的工程价值。

3. **5 角色矩阵进字幕**：B 类的 T-31 不只是后端代码，也变成了销售故事。客户看完 5 分钟视频会知道"这个 Agent 不是越权 AI——它有 5 角色权限边界，AdoptScheduling 只能 Planner/Admin，ExecuteQualityDisposition 只能 Quality/Admin，等等"。
