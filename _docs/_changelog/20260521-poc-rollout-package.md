# 2026-05-21 POC 转上线交付行动包

## 背景

POC 评分表签署后，系统此前已经能证明“演示通过”，但还缺少客户交付团队真正需要的下一步：谁在什么时间内完成上线启动会、接口映射、首批真实工单运行和治理审计。为了让 POC 不停在售前结论，本次把“签署后转试点上线”做成结构化行动包。

## 变更

- 新增 `poc-rollout-package-sync.ts`，保存 `aimes_poc_rollout_package`，并把交付包同步写入统一 `OTD 复盘证据链`。
- `报表中心` 的 POC 区域在复盘签署后展示 `生成上线交付行动包`，生成后显示：
  - `T+7 / T+14` 上线窗口。
  - POC 评分、客户工单/设备样例、OTD 证据链组成的上线门禁。
  - 交付项目、数据接口、现场运行、治理审计四类责任动作。
  - `AUD-POC-ROLLOUT-20260521` 与 `TRACE-POC-ROLLOUT-DELIVERY-PACKAGE-20260521`。
- `AI 生产助手` 可回答 POC 上线交付行动包的上线窗口、门禁、负责人、审计追踪和行动清单。
- `系统管理` Agent 治理新增 POC 上线交付治理卡，展示上线窗口、审计编号和责任动作数量。
- `报表中心` CSV 导出新增 `POC上线交付包` 与 `POC上线交付动作` 行。
- `审计日志` 复用统一 OTD 证据链，自动回放 POC 上线交付包的阶段、对象、来源、追踪编号和状态。

## 验证

- `npx vue-tsc --noEmit -p tsconfig.json`：通过。
- `npm run test:e2e -- tests/e2e/report.spec.ts -g "POC 复盘签署后生成上线交付行动包"`：通过。

## 风险

- 目前交付包仍是本地演示态数据，未接后端持久化和真实项目计划表。
- 完整 `report.spec.ts` 在一次全量运行中出现过旧 CSV 下载用例首跑超时、重试通过；需在后续全量回归中继续观察。
