## 战略愿景：三层架构重构制造生产力

参考业界"系统CLI化、流程Skill化、员工Agent化"的企业AI落地范式，AIMes 的进化路径不是"给 MES 加 AI 功能"，而是**以 Agent 编排为核心，重新定义制造现场的人机协作方式**。

```
┌──────────────────────────────────────────────────────┐
│                  员工 Agent 化                        │
│  调度员Agent │ 车间主管Agent │ 质检Agent │ 设备Agent  │
│   "指挥官": 审核建议、处理异常、优化规则              │
├──────────────────────────────────────────────────────┤
│                  流程 Skill 化                        │
│  排产Skill │ 异常处置Skill │ 齐套检查Skill │ ...      │
│  触发条件 + 规则引擎 + CLI编排 + 异常处理 + 反馈     │
├──────────────────────────────────────────────────────┤
│                  系统 CLI 化                          │
│  REST API → 意图级命令 → MCP协议 → 统一CLI网关        │
│  scheduling.optimize | production.report | ...       │
├──────────────────────────────────────────────────────┤
│              现有业务模块（不变）                       │
│  生产 │ 质量 │ 设备 │ 库存 │ 采购 │ BOM │ 工艺        │
└──────────────────────────────────────────────────────┘
```

**关键原则：**
- CLI 层只负责执行，不拥有业务判断权
- Skill 是业务能力的原子化封装，可复用、可编排、可审计
- Agent 继承岗位权限，主动感知场景，调度 Skill，调用 CLI
- 人从"跑流程的人"变为"指挥 Agent、审核异常、优化规则的人"

## 当前差距（三维度评估）

| 维度 | 当前 V1 | 目标状态 |
|------|---------|----------|
| **CLI 化** | 完整 REST API，但为前端 CRUD 设计；缺意图级命令抽象 | 统一 CLI 网关：意图级命令、MCP 协议、幂等键、机器操作审计 |
| **Skill 化** | Application 层按模块横向切分；缺跨模块流程封装 | Skill 注册中心：触发条件 + 规则引擎 + CLI 编排 + 异常处理 + 反馈回路 |
| **Agent 化** | 4 角色 + AI 被动按钮触发；`AiDecisionTrace` 基础追溯 | 岗位 Agent 运行时：事件监听 → 场景感知 → Skill 调度 → CLI 执行 → 人审核 |
| **业务链路** | 模块并列，弱联动 | 订单到交付的全链路闭环 |
| **数据** | 单页演示数据 | 真实工厂情景数据集 |
| **工作台** | 菜单式模块 | 按角色组织任务和决策 |
| **可追溯** | 基础审计 | AI 建议 → 采纳/拒绝 → 效果回写 → 知识沉淀，完整闭环 |

## 一、系统 CLI 化：MES 可编程操作协议

### 目标

让 AIMes 的所有业务能力不仅能被人通过 GUI 调用，也能被 Agent 通过标准化命令接口调用。
不是另起一套 API，而是在现有 REST API 之上叠加一层**面向机器的操作协议**。

### 行业参照

- **钉钉/飞书/企业微信**相继开源官方 CLI 工具，将消息、文档、审批、会议等核心功能封装为标准化命令，供 AI Agent 直接调用——主流办公平台正从"给人用的 GUI"向"给 AI 用的 CLI 原生平台"演进。
- **阿里云** 80% 以上的 AI 云资源调度已通过 CLI 完成，CLI 成为 AI 交互的核心通道。
- **衡石 HENGSHI** 推出数据分析 CLI，让 AI Agent 操作数据的同时，业务人员也能通过简单命令自主完成分析。
- **畅捷通**将上千个 API 封装为原子 CLI 命令，ISV 无需深入理解复杂 API 即可快速集成。

> **启示**：AIMes 的 CLI 化不是自说自话，而是顺应平台级趋势。MES 领域的 CLI 标准化目前仍是空白，先发优势明确。

### V1 已有基础

- 完整的 REST API（`/api/v1/scheduling`, `/api/v1/production`, `/api/v1/quality` 等 14 个模块）
- JWT 认证 + 4 角色权限
- 审计日志（操作追踪、JSON diff）
- SignalR 实时通知
- Swagger 文档

### 差距与行动

| 能力 | 当前 | 目标 |
|------|------|------|
| 命令抽象 | CRUD 风格 API | 意图级命令：`scheduling.optimize`, `production.report-progress`, `quality.log-inspection` |
| 机器调用安全 | JWT 人类用户 | 新增 API Key / Service Account + 角色绑定，Agent 以用户身份代理执行 |
| 幂等性 | 无 | 幂等键（Idempotency-Key header），安全自动重试 |
| MCP 协议 | 无 | 实现 MCP Server，让外部 AI Agent 发现并调用 MES 能力 |
| CLI 网关 | 无 | 统一网关层：身份认证、权限校验、限流熔断、操作审计、命令路由 |
| 操作审计 | 人类操作 | 扩展 `AuditLog` 记录 `InitiatedBy=Agent`、Agent ID、Skill ID、采纳决策 |

### 实施优先级

1. **命令注册与发现** — 定义 `IMesCommand` 接口，扫描并注册所有业务命令
2. **幂等键** — 中间件层支持，关键写操作强制携带
3. **MCP Server** — 暴露 MES 能力供 AI Agent 工具调用
4. **CLI 网关** — 统一入口，聚合认证/限流/审计/路由

## 二、流程 Skill 化：MES 业务能力封装

### 目标

将散落在 Application 服务、领域实体和业务规则中的"如何完成一件事"封装为可复用、可编排、可审计的标准化 Skill。

### Skill 标准模型

```
Skill {
  id: "material-shortage-resolution"
  name: "缺料处置"
  trigger: { event: "inventory.material-shortage", conditions: [...] }
  rules: [ 安全库存校验, 替代料匹配, 采购周期计算, 影响工单评估 ]
  actions: [ inventory.check-stock, purchase.query-order, scheduling.replan ]
  exceptions: [ 无替代料→升级, 采购周期>3天→预警 ]
  feedback: { onAdopt, onReject, effectMeasurement }
}
```

### 行业参照

- **商越科技**将采购全场景（战略寻源、供应商管理、合同发票、履约协同）封装为 Skill。采购人员通过自然语言提出需求，Skill 自动匹配供应商、生成寻源方案，替代大量人工整理比对。
- **TDengine** 将"UI 设计规范检查""一键搭建演示系统"等复杂工作封装为 Skill，员工通过自然语言指令即可让 AI 自动完成，将个人经验转化为组织资产。
- **腾讯云平台**有企业将数据质量稽查、NL2SQL 即席问答、报告自动生成等多个 Skill 串联，构建了"分钟级高管数据汇报"全自动化工作流。

> **启示**：Skill 的核心价值在于将"只有某个人知道怎么做"变成"组织可复用的数字资产"。AIMes 的 6 个候选 Skill（排产、缺料、质量异常、设备故障、交期风险、齐套检查）正是制造现场最需要沉淀的组织智慧。

### V1 可封装的候选 Skill

| Skill | 涉及模块 | 触发条件 | 核心动作 |
|-------|----------|----------|----------|
| **排产优化** | scheduling, bom, routing, inventory | 新工单 / 插单 / 设备故障 | 多策略生成 → 对比 → 推荐 → 下发 |
| **缺料处置** | inventory, purchase, scheduling | 齐套检查不通过 | 查替代料 → 催采购 → 建议重排 |
| **质量异常闭环** | quality, production, equipment | SPC 超阈值 / 缺陷率超标 | 隔离批次 → 根因推断 → 纠正措施 |
| **设备故障响应** | equipment, scheduling, production | 设备停机 | 评估影响工单 → 建议重排 → 触发维护工单 |
| **交期风险评估** | scheduling, production, inventory, purchase | 进度偏差 > 阈值 | 评估影响 → 预警升级 → 建议插单/外协 |
| **物料齐套检查** | inventory, bom, purchase | 工单排产前 | BOM 展开 → 库存匹配 → 缺料清单 → 预计到货 |

### 差距与行动

| 能力 | 当前 | 目标 |
|------|------|------|
| Skill 注册中心 | 无 | `SkillRegistry`：Skill 的注册、发现、版本管理 |
| 规则引擎 | 散落在 Service 中 | 轻量级规则引擎（json-rules-engine 或自研），规则可配置、可测试 |
| 流程编排 | 无 | Skill 内 CLI 动作的有向无环图（DAG）编排，支持并行/条件/重试 |
| 异常处理 | 各自 try-catch | 标准化 Skill 异常分级：可自动重试 / 需人工介入 / 需升级 |
| 反馈回路 | `AdoptionFeedbackService`（排程专用） | 通用 `SkillFeedback`：采纳、拒绝、效果回写、知识沉淀 |
| 低代码 Skill 开发 | 无 | 长期目标：Skill Builder 让业务专家参与封装 |

## 三、员工 Agent 化：MES 岗位智能副手

### 目标

为每个制造岗位配置一个理解其职责、继承其权限、能主动感知场景并调度 Skill 的专属 Agent。
**不是构建一个万能 AI，而是构建一个由岗位执行代理组成的可控体系。**

### 行业参照（制造业重点）

**产线场景：**
- **固纬电子**在精密仪器生产线上部署"智慧产线助理-Agentic AI"，解决少量多样、频繁换线的生产痛点，将核心品质指标"插件不良返修率"改善了 **50%**。这是目前最接近 AIMes 目标场景的落地案例。
- **百胜中国**发布餐厅营运智能体"Q睿"，与穿戴式设备协同，覆盖排班、盘点、自动订补货、智能安防等 20 余个运营场景，为餐厅经理提供全方位辅助——本质上就是"车间主管 Agent"的餐饮版。

**客服/服务场景（Agent 闭环范式参考）：**
- **网易云商**为时尚零售 I.T 部署客服 Agent，处理售前尺码推荐、售后订单取消等复杂场景，将单次咨询处理时长从 **7 分钟降至 3 分钟**。
- **天润融通**为某智能锁客户拦截了 **90% 以上**的在线咨询，为某空调品牌将客服培训周期缩短一半。

**知识工作场景：**
- **深演智能 Deep Agent 3.0**拥有二十余款智能体，覆盖 7 大领域。其 AI 消费者调研能模拟海量用户进行产品包装测试，将原本需数千人数周的调研缩短至半小时。
- **度小满"原力平台"**让员工无需代码即可创建智能体，内部已生成上百个业务智能体。
- **容联云**为长江证券落地开户质检回访 Agent，自动完成服务质量实时监控、录音抽检与评分。

> **启示**：固纬电子的 50% 缺陷率改善和百胜 Q睿的 20+ 运营场景覆盖，直接验证了"制造岗位 Agent"的价值。AIMes 的 6 类岗位 Agent 设计有坚实的行业证据。

### Agent 运行时模型

```
Agent {
  role: "调度员" | "车间主管" | "质检员" | "设备工程师" | "仓储/采购" | "管理层"
  permissions: <继承岗位 RBAC>
  skills: [ 可调度的 Skill 列表 ]
  eventSubscriptions: [ 新工单, 质量异常, 设备停机, 物料短缺, 交期偏差 ]
  taskQueue: [ 待处理建议, 待审核决策 ]
  
  loop: 监听事件 → 匹配 Skill → 推理 → 生成建议 → 推送 → 等待审核 → 执行/反馈
}
```

### 六类岗位 Agent

| Agent | 主动感知 | 核心 Skill | 输出 |
|-------|----------|------------|------|
| **调度员 Agent** | 新工单、插单、设备故障、物料短缺 | 排产优化、交期风险评估 | 多方案对比 + 推荐 + 影响分析 |
| **车间主管 Agent** | 报工偏差、工序阻塞、人员缺勤 | 产能平衡、工序重排 | 今日派工调整 + 异常升级 |
| **质检员 Agent** | SPC 漂移、缺陷率超标、新批次 | 质量异常闭环 | 隔离建议 + 根因推断 + 纠正措施 |
| **设备工程师 Agent** | 设备停机、健康评分下降、维护到期 | 设备故障响应 | 影响评估 + 维修建议 + 备件需求 |
| **仓储/采购 Agent** | 库存低于安全线、到货延迟、齐套失败 | 缺料处置、齐套检查 | 补货建议 + 替代料推荐 + 催办 |
| **管理层 Agent** | 交期偏差、OEE 下降、质量成本异常 | 交期风险评估 | 全局风险热力图 + 决策建议 |

### 人机协同模式

```
高风险决策（如插单、更换供应商）    → Agent 建议 + 人审核批准
中风险操作（如调整排产参数）        → Agent 建议 + 人确认
低风险操作（如数据记录、状态同步）  → Agent 自动执行 + 事后通知
```

### 差距与行动

| 能力 | 当前 | 目标 |
|------|------|------|
| Agent 运行时 | 无 | `AgentRuntime`：事件总线订阅、任务队列、Skill 调度、状态管理 |
| 事件总线 | SignalR（仅前端通知） | 后端事件总线（MassTransit/RabbitMQ）：业务事件发布/订阅 |
| 场景感知 | 无 | Agent 基于事件 + 业务规则判断是否触发 Skill |
| 任务队列 | 无 | 每个 Agent 一个待办队列：建议、审核、执行结果 |
| Agent 通信 | 无 | Agent 间消息传递：调度员 Agent ↔ 车间主管 Agent 协同 |
| Agent 效果度量 | 无 | 采纳率、平均决策时间、误报率、自动化覆盖率 |

## 四、生产主链路打通

### 功能

- 工单创建后自动关联产品 BOM、工艺路线、设备能力和人员班组。
- 排产前做物料齐套、设备可用、工艺路线完整性、质检点、交期约束检查。
- 排产结果下发到生产报工、质量检验、异常管理和库存预占。
- 报工、质检、异常、设备停机反向触发重排建议。

### 关键页面

- **生产主链路视图**：订单 → BOM → 工艺 → 齐套 → 产能 → 排产 → 下发 → 报工 → 质检 → 异常 → 重排
- **工单详情页**：显示 BOM、路线、物料、设备、质量点、风险和 Agent 建议

### 后端缺口

- `WorkOrderAggregate`：聚合工单、BOM、Routing、Schedule、Inspection、Anomaly
- `MaterialReadinessService`：计算缺料、可替代料、预计到货
- `DispatchService`：排产方案下发和执行状态跟踪

### 验收

- 新建工单后能看到完整链路状态
- 缺料/设备不可用时不能无提示排产
- 报工或异常会影响工单链路状态

## 五、AI 排产中心（调度员 Agent 核心场景）

### 功能

- 同时生成 EDD、SPT、WSPT、瓶颈优先、最小换型、物料优先、平衡交付等候选方案
- 对比交期达成率、设备稼动率、换型时间、瓶颈占用、缺料风险、质量风险
- 支持插单、设备故障、物料短缺、质量返工场景下的重排
- Agent 解释为什么选这个方案，以及被牺牲的目标是什么

### 页面布局

```
┌─────────────┬──────────────────────┬──────────────────┐
│  工单池      │   甘特图/设备时间轴    │  Agent 方案面板   │
│  - 约束冲突   │                      │  - 方案对比        │
│  - 优先级     │                      │  - 雷达图          │
│              │                      │  - 解释文本        │
│              │                      │  - [采纳] [拒绝]   │
├─────────────┴──────────────────────┴──────────────────┤
│  冲突列表 + 可执行修复动作                              │
└──────────────────────────────────────────────────────┘
```

### 后端缺口

- `ScheduleScenario`：保存候选方案和目标函数值
- `ConstraintViolation`：标准化约束冲突
- `ScheduleDecisionTrace`：记录 AI/规则决策、输入、输出、采纳结果

### 验收

- 同一批工单至少能生成 3 个候选方案
- 用户能看到方案差异和 Agent 解释
- 采纳方案后可下发执行，拒绝方案需记录原因

## 六、AI 异常闭环

### 功能

- 异常自动分级：设备、质量、物料、工艺、人员、交期
- Agent 基于工单、设备、质检、物料批次和历史异常推断根因
- 输出处置建议、责任人、预计恢复时间、对交期影响
- 处置后验证效果并沉淀知识库

### 页面布局

- **异常队列**：按严重度、影响工单、影响交期排序
- **异常详情**：时间线、根因树、建议动作、采纳记录
- **异常战情室**：跨部门协同，记录责任人和截止时间

### 后端缺口

- `AnomalyLifecycle`：Open → Acknowledged → Contained → Resolved → Verified → Closed
- `RootCauseGraph`：异常根因和证据
- `CorrectiveAction`：纠正预防措施和效果验证

### 验收

- 异常能进入标准生命周期
- Agent 建议必须能采纳/拒绝并写入追踪
- 已解决异常必须有根因、措施和验证结果

## 七、真实工厂演示数据集

## 八、角色工作台和 UI/UX 布局

### 设计原则

- 面向重复使用的生产运营工具，不做营销式页面
- 信息密度高但层级清晰，优先扫描、比较、执行
- 关键操作固定在上下文旁边，不让用户跨模块找按钮
- Agent 建议必须和证据、影响、采纳动作放在同一视图
- 首屏回答：今天交付是否有风险？风险在哪里？Agent 建议做什么？谁负责？

### 角色工作台

| 角色 | 工作台核心 | 关键指标 |
|------|-----------|----------|
| 调度员 | 工单池、约束冲突、Agent 方案、甘特图、下发 | 交期达成率、排产采纳率 |
| 车间主管 | 今日派工、执行偏差、异常升级、人员负载 | 计划完成率、异常响应时间 |
| 质检员 | 检验任务、SPC 漂移、返工隔离、质量追溯 | 合格率、缺陷率趋势 |
| 设备工程师 | 健康评分、预测维护、停机恢复 | OEE、MTBF、MTTR |
| 仓储/采购 | 齐套、缺料、到货、替代料 | 齐套率、库存周转 |
| 管理层 | 交期、OEE、质量、成本、Agent 采纳率 | 自动化覆盖率、Skill 复用率 |

### 验收

- 任一角色能在 2 次点击内进入自己的待办
- 页面保留全局导航、搜索、班次、Agent 状态和关键动作

## 分阶段实施

### Phase 1：CLI 基础 + 生产主链路（当前 → 2026Q3）

**目标**：建立机器可编程的操作协议，打通订单到交付的核心数据链路。

- 定义 `IMesCommand` 接口，注册核心业务命令
- 实现幂等键中间件
- 扩展 `AuditLog` 支持 Agent 操作审计
- `WorkOrderAggregate` + `MaterialReadinessService` + `DispatchService`
- 生产主链路视图（后端 + 前端）
- 扩展真实演示数据集（按第七节规模）

**验收**：
- 核心写操作支持幂等键
- 审计日志区分人类/AI操作
- 新建工单能看到完整链路状态

---

### Phase 2：Skill 框架 + AI 排产闭环（2026Q3-Q4）

**目标**：建立 Skill 抽象层，以排产场景为首个完整 Skill。

- `SkillRegistry`：注册、发现、版本管理
- 轻量级规则引擎
- Skill 执行引擎（DAG 编排、并行、重试）
- `ScheduleScenario` + `ConstraintViolation` + `ScheduleDecisionTrace`
- 排产优化 Skill（多策略生成 → 对比 → 推荐 → 采纳/拒绝）
- 调度员 Agent 原型：事件监听 + 场景感知 + 建议生成

**验收**：
- 排产 Skill 跑通完整闭环：触发 → 多方案 → Agent 推荐 → 人采纳/拒绝 → 下发
- 同一批工单至少 3 个候选方案
- Skill 采纳/拒绝有完整追踪

---

### Phase 3：Agent 运行时 + 异常/质量闭环（2026Q4-2027Q1）

**目标**：构建 Agent 运行时，实现多 Agent 协同。

- `AgentRuntime`：事件总线、任务队列、Skill 调度
- 后端事件总线完善（MassTransit/RabbitMQ 事件驱动）
- `AnomalyLifecycle` + `RootCauseGraph` + `CorrectiveAction`
- 质量异常闭环 Skill + 设备故障响应 Skill
- 质检员 Agent + 设备工程师 Agent + 车间主管 Agent
- Agent 间通信：异常升级 → 调度员 Agent 重排建议

**验收**：
- 异常从触发到关闭全生命周期追踪
- 至少 3 类 Agent 能主动感知事件并生成建议
- 跨 Agent 协同至少 1 个场景（如设备故障 → 调度重排）

---

### Phase 4：角色工作台 + MCP 协议（2027Q1-Q2）

**目标**：完成 6 类角色工作台，暴露 MCP Server。

- 6 类角色工作台前端实现
- MCP Server：暴露 MES 能力供外部 AI Agent 调用
- Skill 反馈回路完善：效果回写 + 知识沉淀
- 缺料处置 Skill + 交期风险评估 Skill + 物料齐套检查 Skill
- 仓储/采购 Agent + 管理层 Agent

**验收**：
- 任一角色 2 次点击进入待办
- MCP Server 可被外部 Agent 工具调用
- 6 类 Agent 全部上线

---

### Phase 5：可演示产品化 + 低代码 Skill 开发（2027Q2-Q3）

**目标**：端到端演示完整，提供 Skill Builder。

- 端到端演示脚本（20 分钟）
- 一键重置演示数据
- Skill Builder（低代码/无代码 Skill 开发平台）
- Agent 效果仪表盘（采纳率、自动化覆盖率、决策时间、误报率）
- 完整文档和部署说明

**验收**：
- 演示覆盖至少 3 个 Agent 价值场景
- 业务专家可参与 Skill 创建
- README 和部署文档同步

## 组织与度量

### 新角色

| 角色 | 职责 |
|------|------|
| **AI 流程架构师** | 横跨业务、技术、风控；规划 CLI 化优先级、梳理流程 Skill、设计 Agent 自动化链路 |
| **Skill 开发员** | 将业务专家的流程知识封装为可执行 Skill（可兼职，业务专家 + 低代码平台） |
| **Agent 训练员** | 各岗位员工日常训练和优化自己的岗位 Agent、处理 Agent 无法解决的复杂异常 |

### 新度量指标

| 指标 | 定义 | 目标 |
|------|------|------|
| **自动化覆盖率** | Agent 自动处理的任务 / 全部可自动化任务 | Phase 5 达到 60%+ |
| **Agent 采纳率** | 采纳 Agent 建议次数 / Agent 总建议次数 | Phase 5 达到 70%+ |
| **Skill 复用率** | 被 2+ Agent 使用的 Skill 数 / 总 Skill 数 | 鼓励跨岗位复用 |
| **人工重复操作替代率** | 因 Agent 减少的人工重复操作 | 定性评估 + 日志对比 |
| **异常响应时间** | 异常从触发到首次响应 | 目标 < 5 分钟（Agent 自动） |

| **Agent 化（服务）** | 网易云商 / I.T 集团 | 客服 Agent，单次咨询时长 **7→3 分钟** | Agent 实测 50%+ 效率提升，AIMes 的效率指标有锚点 |
| **Agent 化（服务）** | 天润融通 | 智能锁客户在线咨询拦截率 **90%+** | 验证 Agent 在窄场景的高拦截率可达成 |

| **Agent 化（合规）** | 容联云 / 长江证券 | 开户质检回访 Agent，自动监控录音抽检评分 | 合规与审计场景 Agent 化模板可参考 |

### 平台与生态信号

| 信号 | 来源 | 对 AIMes 的启示 |
|------|------|----------------|
| **MCP 协议**（Anthropic / OpenAI） | AI Agent 工具调用标准化 | AIMes 应实现 MCP Server，接入主流 Agent 生态 |
| **Microsoft Copilot Studio** | 自然语言生成工作流 + 关键决策点调用 Agent 推理 | "确定性流程 + 灵活 AI 判断"模式与 AIMes 的"规则引擎 + Agent"思路完全一致 |
| **Gartner AIR 框架** | 记录系统（数据层）+ 行动系统（执行层）+ 智能系统（推理层） | 与 CLI-Skill-Agent 异曲同工，AIMes 路线图获得权威架构验证 |
| **阿里"悟空" Agent 平台** | 钉钉全面 CLI 化 → Agent 原生操作上千能力 | MES 领域尚无类似平台，先发优势窗口仍开放 |
| **销售易 CRM CLI** | AI Agent 在 CRM 中"动手"批量分配线索 | 验证 CLI→Agent 在企业软件领域的可行性 |
| **中信证券数字员工矩阵** | "研产供销服"全价值链 Agent | 全链路 Agent 协同是制造业 MES 的未来形态 |
| **毕马威 AI 就绪度报告** | 70% 企业未做好 AI Ready | AIMes 定位"开箱即用 AI MES"，降低工厂 AI 门槛 |

### 关键对标洞察

1. **制造业 Agent 已有实证**：固纬电子 50% 缺陷率改善，意味着 AIMes 的产线 Agent 不是空想，而是有可量化业务价值的方向。
2. **岗位 Agent 容量被低估**：百胜"Q睿" 单 Agent 覆盖 20+ 场景，AIMes 的 6 类岗位 Agent 设计可以更进取。
3. **平台开放是基础设施层趋势**：钉钉/飞书/企业微信集体 CLI 化、Copilot Studio 工作流融合 Agent，这些不是单点尝试而是**集体共识**。
4. **架构理念已被权威验证**：Gartner AIR 框架与 CLI-Skill-Agent 同构，路线图选型风险低。
5. **低代码 Skill/Agent 平台是中长期标配**：度小满"原力"和畅捷通的实践都指向同一个方向——业务专家最终要能自己造 Agent。
