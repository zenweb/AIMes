# AIMes AI MES Gap and Roadmap

## 目标

把 V1 从“MES 演示看板”推进到“AI MES 指挥系统”。验收标准不是页面数量，而是系统能围绕订单交付自动串联 BOM、工艺、库存、产能、质量、设备、异常和采购，并让 AI 给出可解释、可采纳、可追溯的生产决策。

## 当前差距

| 维度 | 当前 V1 | AI MES 目标 |
| --- | --- | --- |
| 业务链路 | 模块并列，弱联动 | 订单到交付的全链路闭环 |
| AI 能力 | 局部按钮和演示分析 | 排产、异常、质量、设备、库存多场景决策 |
| 数据 | 单页演示数据 | 真实工厂情景数据集 |
| 工作台 | 菜单式模块 | 按角色组织任务和决策 |
| 可追溯 | 基础审计 | AI 建议、采纳、拒绝、效果回写 |

## 1. 生产主链路打通

### 功能

- 工单创建后自动关联产品 BOM、工艺路线、设备能力和人员班组。
- 排产前做物料齐套、设备可用、工艺路线完整性、质检点、交期约束检查。
- 排产结果下发到生产报工、质量检验、异常管理和库存预占。
- 报工、质检、异常、设备停机反向触发重排建议。

### 关键页面

- 生产主链路视图：订单 -> BOM -> 工艺 -> 齐套 -> 产能 -> 排产 -> 下发 -> 报工 -> 质检 -> 异常 -> 重排。
- 工单详情页：显示 BOM、路线、物料、设备、质量点、风险和 AI 建议。

### 后端缺口

- WorkOrderAggregate：聚合工单、BOM、Routing、Schedule、Inspection、Anomaly。
- MaterialReadinessService：计算缺料、可替代料、预计到货。
- DispatchService：排产方案下发和执行状态跟踪。

### 验收

- 新建工单后能看到完整链路状态。
- 缺料/设备不可用时不能无提示排产。
- 报工或异常会影响工单链路状态。

## 2. AI 排产中心

### 功能

- 同时生成 EDD、SPT、WSPT、瓶颈优先、最小换型、物料优先、平衡交付等候选方案。
- 对比交期达成率、设备稼动率、换型时间、瓶颈占用、缺料风险、质量风险。
- 支持插单、设备故障、物料短缺、质量返工场景下的重排。
- AI 解释为什么选这个方案，以及被牺牲的目标是什么。

### 页面布局

- 左侧：工单池和约束冲突。
- 中间：甘特图/设备时间轴。
- 右侧：AI 方案比较、解释、采纳按钮、影响范围。
- 底部：冲突列表和可执行修复动作。

### 后端缺口

- ScheduleScenario：保存候选方案和目标函数。
- ConstraintViolation：标准化约束冲突。
- ScheduleDecisionTrace：记录 AI/规则决策、输入、输出、采纳结果。

### 验收

- 同一批工单至少能生成 3 个候选方案。
- 用户能看到方案差异和 AI 解释。
- 采纳方案后可下发执行，拒绝方案需记录原因。

## 3. AI 异常闭环

### 功能

- 异常自动分级：设备、质量、物料、工艺、人员、交期。
- AI 基于工单、设备、质检、物料批次和历史异常推断根因。
- 输出处置建议、责任人、预计恢复时间、对交期影响。
- 处置后验证效果并沉淀知识库。

### 页面布局

- 异常队列：按严重度、影响工单、影响交期排序。
- 异常详情：时间线、根因树、建议动作、采纳记录。
- 异常战情室：跨部门协同，记录责任人和截止时间。

### 后端缺口

- AnomalyLifecycle：Open -> Acknowledged -> Contained -> Resolved -> Verified -> Closed。
- RootCauseGraph：异常根因和证据。
- CorrectiveAction：纠正预防措施和效果验证。

### 验收

- 异常能进入标准生命周期。
- AI 建议必须能采纳/拒绝并写入追踪。
- 已解决异常必须有根因、措施和验证结果。

## 4. 真实工厂演示数据集

### 数据规模

- 产品：5 个以上，覆盖装配件、机加工件、外购件。
- BOM：20+ 物料，支持多级 BOM、替代料、损耗率。
- 工艺路线：10+ 路线，包含质检点、设备类型、标准工时、换型时间。
- 设备：8+ 台，包含瓶颈设备、维护窗口、故障场景。
- 工单：30+ 单，覆盖正常、插单、延期、返工、缺料。
- 异常：15+ 条，覆盖设备、质量、物料、工艺。
- 采购/库存：到货计划、安全库存、缺料预警、替代料。

### 验收

- 演示数据能支撑 20 分钟端到端演示。
- 至少包含 3 个能体现 AI 价值的冲突场景。
- 重置数据库后数据可重复生成。

## 5. 角色工作台和 UI/UX 布局

### 设计原则

- 面向重复使用的生产运营工具，不做营销式页面。
- 信息密度高但层级清晰，优先扫描、比较、执行。
- 关键操作固定在上下文旁边，不让用户跨模块找按钮。
- AI 建议必须和证据、影响、采纳动作放在同一视图。

### 角色

- 调度员：工单池、约束冲突、AI 方案、甘特图、下发。
- 车间主管：今日派工、执行偏差、异常升级、人员负载。
- 质检员：检验任务、SPC 漂移、返工隔离、质量追溯。
- 设备工程师：健康评分、预测维护、停机恢复。
- 仓储/采购：齐套、缺料、到货、替代料。
- 管理层：交期、OEE、质量、成本、AI 采纳率。

### 前端升级位置

- Nuxt + Tailwind CSS + PrimeVue 主前端：`src/frontend/`
- 当前策略是迁移现有 Vue 业务组件，避免另起 React 技术路线。

### 验收

- 首屏能回答：今天交付是否有风险、风险在哪里、AI 建议做什么、谁负责。
- 任一角色能在 2 次点击内进入自己的待办。
- 页面保留全局导航、搜索、班次、AI 状态和关键动作。

## 分阶段实施

### Phase 1：AI MES 骨架

- 建立生产主链路模型。
- 扩展真实演示数据。
- 完成 React 原型评审，决定是否迁移现有 Vue 或新建 React 前端。

### Phase 2：AI 排产闭环

- 多策略候选方案。
- 约束冲突解释。
- 采纳/拒绝追踪。

### Phase 3：异常和质量闭环

- 异常生命周期。
- 根因推理和纠正措施。
- 质量漂移预测。

### Phase 4：角色工作台

- 调度、车间、质检、设备、仓储采购、管理层工作台。
- 指标和操作按角色裁剪。

### Phase 5：可演示产品化

- 端到端演示脚本。
- 一键重置演示数据。
- README 和部署说明同步更新。
