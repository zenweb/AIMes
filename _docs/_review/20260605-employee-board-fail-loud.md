# 2026-06-05 EmployeeBoard Fail-loud Review

## Findings

- 审计结论：本片修复员工创建接口失败时“本地假成功”的问题，避免人员档案未写入后端却在页面上出现新员工。
- 行为覆盖：`createEmployee()` 抛错后，创建弹窗必须保持打开，页面不能出现新工号 `EMP-900`，并且必须显示 `[role="alert"]`，包含“员工创建失败”和底层错误。
- 审计结论：本片修复员工创建成功后页面不展示新员工的问题，避免用户误以为创建未生效。
- 行为覆盖：`createEmployee()` 成功返回 `EMP-900` 后，创建弹窗必须关闭，人员列表必须展示 `EMP-900` 和“测试员工”。
- 行为保持：本片没有改动导出、过滤、分页、编辑保存或离职逻辑。
- 审计结论：本片修复员工列表初始加载失败时静默 demo fallback 的问题，避免用户把示例员工误认为真实人员档案。
- 行为覆盖：`getEmployeeList()` 抛错后，页面仍可展示 `EMP-001` 等本地示例员工，同时必须显示 `[role="alert"]`，包含“员工列表加载失败”“当前展示本地示例数据”和底层错误。
- 审计结论：本片同时修复员工编辑保存接口失败时“本地假成功”的问题，避免未持久化的姓名、电话、角色、班组或班次变更被页面展示为已保存。
- 行为覆盖：`updateEmployee()` 抛错后，编辑弹窗必须保持打开，页面不能出现未持久化姓名 `张三-误写`，并且必须显示 `[role="alert"]`，包含“员工资料保存失败”和底层错误。
- 审计结论：本片同时修复员工编辑保存成功后页面仍显示旧资料的问题，避免用户误以为保存未生效。
- 行为覆盖：`updateEmployee()` 成功返回“王小明”后，编辑弹窗必须关闭，人员卡片必须展示“王小明”且不再展示旧姓名“张三”。
- 审计结论：本片同时修复员工离职接口失败时“本地假成功”的问题，避免未持久化的离职结果被页面展示为已生效。
- 行为覆盖：`deactivateEmployee()` 抛错后，编辑弹窗必须保持打开，员工仍保留在在职列表，并且必须显示 `[role="alert"]`，包含“员工离职失败”和底层错误。
- 审计结论：本片同时修复员工离职成功后默认在职列表仍显示该员工的问题，避免用户误以为离职未生效。
- 行为覆盖：`deactivateEmployee()` 成功后，编辑弹窗必须关闭，默认在职列表必须从 2 张员工卡变为 1 张，且不再展示“张三”。
- 可访问性覆盖：员工卡片现在具备 button 语义、键盘焦点和 Enter/Space 打开详情能力，避免人员详情入口只对鼠标可用。
