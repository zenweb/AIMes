# 2026-06-05 AdminBoard Fail-loud Review

## Findings

- 审计结论：本片修复系统用户创建接口失败时“本地假成功”的问题，避免系统账号未写入后端却在页面上出现新用户。
- 行为覆盖：`createUser()` 抛错后，创建弹窗必须保持打开，页面不能出现用户名 `qa-admin`，并且必须显示 `[role="alert"]`，包含“用户创建失败”和底层错误。
- 审计结论：本片同时修复系统用户编辑接口失败时“本地假成功”的问题，避免用户资料或角色未写入后端却被页面本地覆盖。
- 行为覆盖：`updateUser()` 抛错后，编辑弹窗必须保持打开，页面不能把 `operator1` 本地改成 `qa-renamed`，并且必须显示 `[role="alert"]`，包含“用户资料保存失败”和底层错误。
- 审计结论：本片同时修复系统用户启停接口失败时“本地假成功”的问题，避免账号启用/禁用状态未写入后端却被页面本地翻转。
- 行为覆盖：`updateUser()` 抛错后，状态列必须保持“启用”，操作按钮必须仍显示“禁用”，并且必须显示 `[role="alert"]`，包含“用户启停失败”和底层错误。
- 审计结论：本片同时修复系统配置保存失败时静默吞错的问题，避免管理员误判配置已落库。
- 行为覆盖：`updateConfig()` 抛错后，配置输入必须保留用户修改值便于重试，并且必须显示 `[role="alert"]`，包含“系统配置保存失败”和底层错误。
- 审计结论：本片同时修复通知配置保存失败时静默吞错和本地假切换的问题，避免通知策略未写入后端却被页面展示为已变更。
- 行为覆盖：`updateNotificationConfig()` 抛错后，重新进入通知页时开关必须保持后端原状态，并且必须显示 `[role="alert"]`，包含“通知配置保存失败”和底层错误。
- 行为保持：成功创建路径仍关闭弹窗并重置表单；成功编辑路径仍关闭编辑弹窗；通知配置成功保存后仍本地切换开关。
