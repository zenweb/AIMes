# 2026-06-14 Issue - 多目标对比同设备计划项时间重叠

## 问题
- `ParetoCompare.vue` 已检查计划项自身时间窗有效，但不检查同一设备上的多个计划项是否互相重叠。
- 当后端返回同一 `equipmentId` 下 08:00-12:00 与 10:00-14:00 的计划时，页面仍会展示推荐卡、KPI 表和“采用”按钮。
- 这会让物理上不可执行的排产方案进入采用路径，后续甘特图、回写和审计解释都缺少可信执行基础。

## 影响
- 用户关键路径：排产看板的多目标方案对比和推荐方案采用。
- 风险类型：同设备并发占用、假可落地方案、采用后执行冲突。
- 严重性：高，属于现有排产功能必须补齐的可靠性缺口。

## 修复
- 增加同设备计划项时间重叠校验。
- 按设备分组后按开始时间排序，只检查相邻任务是否重叠，保持实现简单且可解释。
- 命中时抛出 `后端对比方案同设备计划项时间重叠`。
- catch 分支沿用现有 fail-loud 告警，清空对比项、推荐目标和当前 tab。
- 单测和 Chromium e2e 均断言不展示推荐卡或“采用此方案”按钮。

## 验证
- 单测覆盖“同设备计划项时间重叠”必须 fail-loud。
- Chromium 真实浏览器覆盖该缺陷载荷后展示失败告警。
- 完整排产 Chromium 套件和前端覆盖率总检均通过。
