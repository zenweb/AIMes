# 2026-06-14 Issue - 后端可写入并返回不可审计采纳反馈

## 问题
- `/api/v1/scheduling/adoption-feedback` 旧逻辑只校验计划、车间和原因分类，空白 `ReasonDetail` 仍会返回 201。
- `/api/v1/scheduling/adoption-feedback/latest` 旧逻辑按时间取最新记录，即使最新记录缺少原因说明也会返回给前端。

## 影响
- 排产采纳反馈缺少“为什么采纳/调整”的关键解释，审计和复盘不可用。
- 前端虽然已有 fail-loud 回退，但源头仍可能持续产出不可审计记录。

## 修复
- POST 写入端新增空白原因说明校验。
- latest 读取端过滤缺少原因说明的反馈，返回最近一条可审计记录。
- 集成测试和应用服务测试覆盖写入拒绝、历史脏记录跳过、字段完整性。

## 剩余风险
- 未做历史数据清理；若需要保留所有脏记录的处置证据，应单独设计迁移/修复脚本。
