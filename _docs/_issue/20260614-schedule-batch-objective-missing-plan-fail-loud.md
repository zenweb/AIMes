# 2026-06-14 Issue - 多目标方案缺少计划仍提交采纳反馈

## 问题
- `onApplyObjective` 旧逻辑在用户点击“采用此方案”后，先切换 `currentObjective`、关闭对比弹窗并提交 `batch_optimize_apply` 反馈，然后才触发优化。
- 当优化接口返回 200 但缺少 `plan` 时，页面会展示优化失败，但审计反馈已经记录了“采用此方案”。
- 用户也会看到目标状态已经切换，误以为多目标方案已经进入正式排产。

## 影响
- 用户关键路径：多目标方案对比后的方案采用。
- 风险类型：采纳审计误记录、目标状态误导、优化结果未落地。
- 严重性：中高，属于现有排产功能必须补齐的可靠性和可审计性缺口。

## 修复
- `handleOptimize` 返回优化是否成功。
- `onApplyObjective` 先用待采用目标执行优化；只有成功拿到 `plan` 后才切换目标、关闭对比弹窗并提交采纳反馈。
- 优化失败或缺少 `plan` 时，保留待采纳状态，并展示既有优化失败告警。

## 验证
- 单测覆盖多目标采用后优化缺少 `plan` 时不提交采纳反馈、不关闭对比弹窗、不切换目标。
- Chromium 真实浏览器覆盖同一交互路径，并验证 adoption-feedback 请求数为 0。
