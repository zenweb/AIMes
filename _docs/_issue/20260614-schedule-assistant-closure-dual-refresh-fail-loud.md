# 2026-06-14 Issue - Assistant 闭环双刷新失败反馈可能丢失

## 问题
- Assistant 恢复交接闭环后会刷新恢复包、工程约束包和风险事件。
- 旧实现中恢复包刷新失败和工程约束包刷新失败共用单个 `feedbackSyncNote`，存在互相覆盖风险。
- 工程约束包 API/sync 层默认吞掉后端错误，真实浏览器 503 不会进入闭环刷新失败提示。

## 修复
- 给工程约束包 API/sync 层增加可选 `failLoud`。
- 闭环刷新路径传入 `failLoud`，启动路径保持默认兜底。
- 增加 `appendFeedbackSyncNote`，让多个闭环刷新失败追加展示。
- 闭环语境下工程约束包失败显示为 `Assistant 工程约束闭环刷新失败`。

## 验收
- 单测证明 API/sync 层 fail-loud 会抛出后端错误。
- 组件测试证明两个失败原因同时可见。
- Chromium 真实浏览器证明两个 503 后端错误都显示在页面反馈里。

## 状态
- 已修复并验证通过。
