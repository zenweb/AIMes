# 2026-06-14 Issue - 多目标对比排产计划标识重复

## 问题
- `ParetoCompare.vue` 已检查目标标识唯一性，但不检查多个目标是否复用同一个 `plan.id`。
- 当后端返回 `due_date` 与 `balanced` 指向同一个排产计划标识时，页面仍会展示推荐卡、KPI 表、目标 tab 和“采用此方案”按钮。
- 这会让不同优化目标共享同一个计划身份，后续采用反馈和审计解释无法稳定回答“到底采用了哪个排产方案”。

## 影响
- 用户关键路径：排产看板的多目标方案对比、推荐方案查看和方案采用。
- 风险类型：方案身份歧义、采用反馈归因不清、审计链路不可追溯。
- 严重性：中高，属于现有排产功能必须补齐的正确性和可审计性缺口。

## 修复
- 增加排产计划 ID 唯一性校验。
- 在确认每个对比项都有 `plan` 且 `plan.items` 为数组之后，使用 `Set` 比较 `items.map(item => item.plan.id)` 与原始数组长度。
- 命中时抛出 `后端对比方案排产计划标识重复`。
- catch 分支沿用现有 fail-loud 告警，清空对比项、推荐目标和当前 tab。
- 单测和 Chromium e2e 均断言不展示推荐卡或“采用此方案”按钮。

## 验证
- 单测覆盖“不同 objective 复用同一个 plan.id”必须 fail-loud。
- Chromium 真实浏览器覆盖该缺陷载荷后展示失败告警。
- 完整 ParetoCompare 单测、完整排产 Chromium 套件、前端覆盖率总检均已执行并通过。
