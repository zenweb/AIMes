# 2026-06-14 Issue - 多目标对比排产计划标识缺失

## 问题
- `ParetoCompare.vue` 已检查对比项是否包含 `plan` 和 `plan.items`，但不检查 `plan.id` 是否存在。
- 当后端返回 `plan.id` 为空白字符串时，页面仍会展示推荐卡、KPI 表、目标 tab 和“采用此方案”按钮。
- 这会让没有排产计划身份的方案进入采用路径，后续反馈和审计链路缺少稳定计划锚点。

## 影响
- 用户关键路径：排产看板的多目标方案对比、推荐方案查看和方案采用。
- 风险类型：采纳反馈缺少 `schedulePlanId` 语义基础、审计链路不可追溯、方案身份不完整。
- 严重性：中高，属于现有排产功能必须补齐的正确性和可审计性缺口。

## 修复
- 增加排产计划 ID 缺失校验。
- 在确认每个对比项都有 `plan` 且 `plan.items` 为数组之后，检查 `item.plan.id?.trim()`。
- 命中时抛出 `后端对比方案缺少排产计划标识`。
- catch 分支沿用现有 fail-loud 告警，清空对比项、推荐目标和当前 tab。
- 单测和 Chromium e2e 均断言不展示推荐卡或“采用此方案”按钮。

## 验证
- 单测覆盖“对比方案 plan.id 为空白字符串”必须 fail-loud。
- Chromium 真实浏览器覆盖该缺陷载荷后展示失败告警。
- 完整 ParetoCompare 单测、完整排产 Chromium 套件、前端覆盖率总检均已执行并通过。
