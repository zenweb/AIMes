# 2026-06-14 Issue - 多目标对比计划项循环依赖

## 问题
- `ParetoCompare.vue` 已检查依赖任务存在和计划项不依赖自身，但不检查多节点循环依赖。
- 当后端返回 A 依赖 B、B 依赖 A 的计划项时，页面仍会展示推荐卡、KPI 表和“采用”按钮。
- 这会让执行拓扑不可排序的方案进入采用路径，后续甘特图顺序、审计解释和回写链路缺少可信依赖依据。

## 影响
- 用户关键路径：排产看板的多目标方案对比和推荐方案采用。
- 风险类型：假可落地方案、任务依赖拓扑不可执行、采用后执行顺序和审计说明不可信。
- 严重性：中高，属于现有排产功能必须补齐的可靠性和可审计性缺口。

## 修复
- 增加同一方案计划明细的依赖图 DFS 检测。
- 当发现任意长度循环依赖时抛出 `后端对比方案计划项存在循环依赖`。
- catch 分支沿用现有 fail-loud 告警，清空对比项、推荐目标和当前 tab。
- 单测和 Chromium e2e 均断言不展示推荐卡或“采用此方案”按钮。

## 验证
- 单测覆盖“两节点循环依赖”必须 fail-loud。
- Chromium 真实浏览器覆盖该缺陷载荷后展示失败告警。
- 完整排产 Chromium 套件和前端覆盖率总检均通过。
