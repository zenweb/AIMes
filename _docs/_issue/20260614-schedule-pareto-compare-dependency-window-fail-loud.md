# 2026-06-14 Issue - 多目标对比计划项依赖时间顺序无效

## 问题
- `ParetoCompare.vue` 已检查依赖目标存在、自依赖和循环依赖，但不检查依赖任务是否已经在下游任务开始前完成。
- 当后端返回 A 任务 08:00-12:00、B 任务依赖 A 但 10:00 开始的计划时，页面仍会展示推荐卡、KPI 表和“采用”按钮。
- 这会让依赖链不可执行的排产方案进入采用路径，后续甘特图、回写和审计解释都缺少可信执行基础。

## 影响
- 用户关键路径：排产看板的多目标方案对比和推荐方案采用。
- 风险类型：依赖工序未完成即开工、假可落地方案、采用后执行冲突。
- 严重性：高，属于现有排产功能必须补齐的可靠性缺口。

## 修复
- 增加依赖时间顺序校验。
- 按任务 ID 建索引，逐项检查每个依赖任务的结束时间是否晚于当前任务开始时间。
- 命中时抛出 `后端对比方案计划项依赖时间顺序无效`。
- 自依赖和循环依赖校验优先于依赖时间顺序校验，保留更具体的 fail-loud 信息。
- 单测和 Chromium e2e 均断言不展示推荐卡或“采用此方案”按钮。

## 验证
- 单测覆盖“下游任务早于依赖任务完成前开始”必须 fail-loud。
- Chromium 真实浏览器覆盖该缺陷载荷后展示失败告警。
- 完整排产 Chromium 套件和前端覆盖率总检均通过。
