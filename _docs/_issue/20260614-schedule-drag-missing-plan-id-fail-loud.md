# 2026-06-14 Issue - 拖拽写回缺少排产计划 ID 静默失败

## 问题
- `handleTaskDragEnd` 旧逻辑在 `!task || !planData.value?.id` 时直接返回。
- 当任务存在但当前排产计划缺少 ID 时，用户拖拽任务条后不会触发正式写回，也看不到任何失败原因。
- 这会让调度员误以为拖拽动作已被处理，实际正式排产计划没有更新。

## 影响
- 用户关键路径：真实 dhtmlx 甘特图拖拽写回正式排产计划。
- 风险类型：静默失败、正式写回缺口、生产交接误判。
- 严重性：中高，属于现有排产功能必须补齐的可靠性和可观察性缺口。

## 修复
- 任务不存在时显示 `保存失败: 未找到可写回的排产任务 {taskId}`。
- 当前计划缺少 ID 时显示 `保存失败: 当前排产计划缺少 ID，无法写回任务 {taskId}`。
- 保持成功写回和后端拒绝写回的既有行为不变。

## 验证
- 单测覆盖计划 ID 缺失分支。
- Chromium 真实浏览器覆盖正式 dhtmlx 载荷缺少计划 ID 后拖拽任务条的交互路径。
