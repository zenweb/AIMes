# 2026-06-14 Issue - 多目标对比计划项缺少任务身份标识

## 问题
- `ParetoCompare.vue` 旧逻辑检查了计划项时间窗、工单和设备锚点，但不检查计划项自身 `id` 和 `workOrderNumber`。
- 当后端返回缺少任务 ID 的计划项时，页面仍会展示推荐卡、KPI 表和“采用”按钮。
- 这会让无法稳定识别和展示的任务进入采用路径，后续甘特图、审计和回写链路缺少任务级身份依据。

## 影响
- 用户关键路径：排产看板的多目标方案对比和推荐方案采用。
- 风险类型：假可落地方案、任务无法稳定追踪、采用后反馈链缺少任务身份和工单展示证据。
- 严重性：中高，属于现有排产功能必须补齐的可靠性和可审计性缺口。

## 修复
- 当任一计划项缺少 `id` 或 `workOrderNumber` 时抛出 `后端对比方案计划项缺少任务身份标识`。
- catch 分支沿用现有 fail-loud 告警，清空对比项、推荐目标和当前 tab。
- 单测和 Chromium e2e 均断言不展示推荐卡或“采用此方案”按钮。

## 验证
- 单测覆盖“计划项缺少任务 ID”必须 fail-loud。
- Chromium 真实浏览器覆盖该缺陷载荷后展示失败告警。
- 完整排产 Chromium 套件和前端覆盖率总检均通过。
