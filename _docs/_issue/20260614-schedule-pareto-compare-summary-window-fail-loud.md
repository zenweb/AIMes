# 2026-06-14 Issue - 多目标对比计划摘要时间窗未覆盖明细

## 问题
- `ParetoCompare.vue` 已检查计划项自身时间窗有效，但不检查 `planStartDate` / `planEndDate` 是否覆盖所有计划项。
- 当后端返回摘要时间窗短于明细任务时间窗的计划时，页面仍会展示推荐卡、KPI 表和“采用”按钮。
- 这会让摘要边界与甘特明细不一致的方案进入采用路径，后续计划范围、审计解释和回写链路缺少可信时间依据。

## 影响
- 用户关键路径：排产看板的多目标方案对比和推荐方案采用。
- 风险类型：假可落地方案、计划摘要与明细不一致、采用后排产时间边界和审计说明不可信。
- 严重性：中高，属于现有排产功能必须补齐的可靠性和可审计性缺口。

## 修复
- 增加计划摘要时间窗覆盖校验。
- 当摘要起止时间不可解析、结束不晚于开始，或任一明细任务落在摘要时间窗之外时抛出 `后端对比方案计划摘要时间窗未覆盖计划明细`。
- catch 分支沿用现有 fail-loud 告警，清空对比项、推荐目标和当前 tab。
- 单测和 Chromium e2e 均断言不展示推荐卡或“采用此方案”按钮。

## 验证
- 单测覆盖“摘要时间窗短于计划明细”必须 fail-loud。
- Chromium 真实浏览器覆盖该缺陷载荷后展示失败告警。
- 完整排产 Chromium 套件和前端覆盖率总检均通过。
