# 2026-06-14 Issue - 多目标对比推荐最高分 Fail-Loud

## 问题
- 多目标对比 UI 文案声明推荐方案是“综合得分最高”，但旧逻辑只检查 `bestOverallObjective` 是否存在于 `items`。
- 如果后端推荐了非最高分目标，页面会继续渲染推荐卡并允许“采用此方案”，用户可能采纳错误方案。

## 影响
- 推荐理由、推荐标签和采纳入口会与真实综合得分排序不一致。
- 该问题位于排产多目标对比的用户关键路径，属于现有功能精品化必须收紧的契约缺口。

## 修复
- 前端在渲染推荐前复算综合得分。
- 非最高分推荐直接 fail-loud：`后端推荐方案不是综合得分最高方案`。
- 不渲染推荐卡和采纳按钮。

## 剩余风险
- 综合得分公式目前前后端各维护一份，后续公式变更可能产生漂移。
- 本轮完整 Chromium 套件出现 1 个既有 flaky：feedback warning 首次断言拿到离线 demo warning，retry 后通过。

## 追加 Issue - 推荐理由不可审计
- 问题：推荐卡旧文案只说明“综合得分最高”，缺少综合分与分项构成，用户无法从卡片本身判断推荐依据。
- 处理：推荐卡展示综合分与利用率、准时率、换线、分组、完工率。
- 证据：真实 Chromium 用例已断言上述文本在 `.recommend-card` 中可见。
