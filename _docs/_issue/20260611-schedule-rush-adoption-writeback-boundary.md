# Issue：急单采纳反馈可能被误读为正式计划已执行

## 状态

已处理。

## 问题

急单插单建议采纳后，系统会显示反馈已同步后台并进入 OTD 复盘，但界面没有足够明确地区分“调度员采纳了建议”和“正式排产计划已经写入/保存”。这会让用户误以为采纳动作已经完成生产计划落地。

## 影响

- 调度员可能把复盘反馈当成正式执行。
- 生产交接时缺少“还需要优化或拖拽保存”的边界提醒。
- OTD 证据链虽然完整，但执行状态表达不够精品。

## 处理

- 急单事件建议采纳后的反馈同步提示增加“尚未写入正式排产计划”。
- Agent 工作台执行追踪显示“正式计划待优化或保存”。
- 单测与真实 Chrome e2e 覆盖该边界。

## 验证

- `schedule-board.test.ts` 覆盖急单采纳反馈提示。
- `schedule-agent-workbench-panel.test.ts` 覆盖工作台执行追踪状态。
- `scheduling.spec.ts` 真实 Chrome 覆盖用户实际采纳路径。
